# Согласованный набор симуляции

Этап №57 эпика №56 предоставляет `IExperimentDatasetReader` в существующем модуле
DataCollection. Это читающий контракт приложения, а не HTTP endpoint или торговый
движок. Миграций для него нет.

## Выбор и результат

`ExperimentDatasetRequest` требует точный `CollectorSessionId` и положительный
`ProjectionVersion`. Последняя сессия рынка автоматически не выбирается. Версия
должна совпадать с сохранённой версией сессии; текущая конфигурация normalizer не
подменяет историческую версию. Первая реализация принимает только успешный архив
`Stopped/MarketClosed` без `InvalidatingAt` и failure code. Активные, удалённые и
временно удерживаемые failed datasets не поддерживаются.

`ExperimentDatasetSnapshot` материализует:

- манифест с копией идентичности рынка, расписания и исходов по `OutcomeIndex`;
- независимый отчёт пригодности и исходные счётчики нормализации;
- события существующих моделей стакана в порядке `(raw_message_id, raw_item_index)`;
- канонические JSON-строки всех семи типов проекции, включая финансовые метаданные;
- канонический JSON сохранённых свидетельств подтверждения исхода.

Интеграция с #56 также материализует `RawMessages`: все raw-заголовки с ID,
эпохой, временем получения и hash payload. Они читаются в той же транзакции,
включают пустые массивы и сообщения других типов и не раскрывают исходные bytes.
Это позволяет назначать причинную доступность без повторного чтения архива.
Алгоритм `RawFingerprint` и формат манифеста при этом не меняются.

Исходные payload в результат не входят. Подготовительные события до
`EventStartsAt` входят в набор. Торговое окно имеет границы
`[EventStartsAt, EventEndsAt)`. Фильтрация подготовки и причинное торговое
воспроизведение относятся к следующему этапу №58.

Коллекции результата неизменяемы, включая уровни `BookSnapshotRecord` и элементы
одного атомарного `NormalizedOrderBookEvent.PriceChanges`. Изменение архива после
возврата не изменяет уже возвращённый набор.

Пример вызова в настроенной области зависимостей без запуска hosted services:

```csharp
await using var scope = serviceProvider.CreateAsyncScope();
var reader = scope.ServiceProvider.GetRequiredService<IExperimentDatasetReader>();
var result = await reader.ReadAsync(
    new ExperimentDatasetRequest(
        CollectorSessionId.Create(
            Guid.Parse("33a17de5-2b29-4de2-929c-2d1c0ee46588")).Value,
        ProjectionVersion: 1)
    {
        ExpectedRawFingerprint =
            "c3406bfabd052b82ee46b9842683e013fc82bc8aad93652e22979fe6f24316e5"
    },
    cancellationToken);
```

Идентификатор и отпечаток в примере закреплены в эпике №56. Автоматические тесты
создают собственные PostgreSQL-базы и не доказывают наличие этого архива в среде
оператора. Полученный `ManifestFingerprint` следует сохранить вместе с параметрами
эксперимента и передавать как `ExpectedManifestFingerprint` при повторном открытии.

## Согласованность и неизменность

Читатель владеет одной транзакцией PostgreSQL `RepeatableRead READ ONLY` с локальной
зоной `UTC`. Все зависимости чтения должны использовать тот же scoped
`DataCollectionDbContext`. Уже открытая внешняя транзакция отклоняется, чтобы её
уровень изоляции не ослабил гарантию.

Ни `SaveChanges`, ни normalizer replay, ни внешние REST-запросы, ни lifecycle,
cleanup или runtime coordinators не вызываются. Переиспользуется только читающий
`CollectorOrderBookIntegrityCoordinator`; он проверяет временные состояния
стаканов. Транзакция освобождается при возврате, ошибке и отмене. Длительное
воспроизведение должно работать с результатом после её завершения.

## Отчёт пригодности

Ошибка выбора или чтения возвращается как `Result.Failure`: например,
`experiment.dataset.session_not_found`, `projection_version_mismatch`,
`archive_not_successful`, `raw_fingerprint_mismatch` или
`manifest_fingerprint_mismatch` с общим префиксом `experiment.dataset.`.
Код PostgreSQL сохраняется в суффиксе `experiment.dataset.read_failed.<SQLSTATE>`;
содержимое payload не включается в сообщение. Отмена пробрасывается.

Прочитанный, но непригодный архив возвращает результат с блокирующей диагностикой:

- отсутствуют обязательные метаданные, в том числе legacy `null` версии;
- `RawCount = 0`, отсутствуют записи журнала, не все записи имеют `Processed`
  или у обработанной записи нет `CompletedAt`;
- принадлежность `normalized.session_id` не совпадает с parent raw session;
- время получения заголовка отличается от времени parent raw;
- отсутствует обязательная типизированная строка или есть строка чужого типа;
- неизвестен тип события или версия его нормализатора;
- исторические реквизиты выбранного рынка противоречат его снимку;
- значения нарушают инварианты существующих моделей либо терминальная проверка
  стакана не пройдена.

Полнота означает обработку каждого raw выбранной версией. Она **не** означает
равенство числа normalized events и raw: `Processed` для `[]` допустим без единого
события. При этом пустой массив не заменяет обязательные initial book обоих
токенов. Пропуски глобальных `raw.id` также не означают потерю сообщения: между
ними могут находиться сообщения других сессий. Дополнительные проекции других
версий не меняют выбранный набор.

`IsArchiveUsable` подтверждает отсутствие блокирующих архивных проблем, но не
разрешает торговлю. Терминальная проверка использует существующий ретроспективный
планировщик; она не доказывает пригодность каждого причинного префикса.

Четыре независимых источника сведений имеют `Missing`, `Declared`, `Available` или
`Conflicting`:

- **Resolution:** сохранённое подтверждение с согласованными Gamma/CLOB ссылками,
  идентичностью, исходами, winner и обработанным typed WebSocket signal.
  `Stopped/MarketClosed` не подтверждает исход. Политика расчёта — задача №61.
- **Fees:** архивное объявление именно выбранного рынка с полным `fee_schedule`.
  Сравниваются также condition, event identity и упорядоченные tokens/outcomes.
  Объявления чужих рынков сохраняются в отпечатке, но не задают правила выбранного.
  Наличие сведений не выбирает формулу комиссии или округления: это задача №59.
- **MinimumOrderSize:** в этом архивном контракте нет подтверждённого источника
  минимального размера. `order_price_min_tick_size` не заменяет его.
- **Btc:** внешний поток не загружается этим читателем. Причинность и полнота его
  содержимого проверяются компонентом задачи №62.

Закреплённые внешние ссылки содержат логическое имя и SHA-256. Наличие ссылки на
BTC или профиль означает только `Declared`, не проверку содержимого. `null`
параметров комиссии не превращается в ноль. Явно сохранённый нулевой `fee_schedule`
отличается от отсутствующего.

## Алгоритмы отпечатков, формат 1

Все SHA-256 записываются 64 шестнадцатеричными символами нижнего регистра.

### Исходный архив

Алгоритм эпика №56: SHA-256 от UTF-8 строк, соединённых одним LF **без завершающего
LF**, в порядке `raw.id`:

```text
id:connection_epoch:ReceivedAt(UTC YYYY-MM-DD HH24:MI:SS.US):hex(SHA-256(payload))
```

Payload хешируется PostgreSQL как `bytea`, без разбора или переформатирования JSON.
Изменение любого исходного байта, epoch или времени получения меняет отпечаток.

### Типизированные данные и свидетельства

JSON канонизируется рекурсивно: свойства сортируются ordinal, порядок массивов
сохраняется, числа `decimal` записываются invariant `G29`. `null`, ноль, `false` и
пустая строка различаются. Текст и регистр идентификаторов не нормализуются.

- Ledger: все сохранённые поля записей выбранной версии, по `raw_message_id`.
- Projection: все поля заголовков и типизированных строк, по
  `(raw_message_id, raw_item_index)`. Уровни сортируются по `(side, level_index, id)`,
  остальные дочерние массивы — по `(item_index, id)`. Включены book snapshots/levels,
  price changes, ticks, best bid/ask, last trade, new market/assets и market
  resolution/assets. Хешируются канонические строки с LF между ними.
- Evidence: сохранённая строка сессии, resolution state и observations с исходами.
  Каноническая JSON-строка хешируется целиком.

Отпечатки отражают точный сохранённый архив, включая surrogate IDs и времена его
обработки. Это не переносимый семантический hash независимо пересозданной БД.
Схема типизированных строк и совместимость их чтения закреплены версией алгоритма;
изменение набора полей или правил канонизации требует повышения версии.
Поддерживаются normalizer versions `1` и для `new_market` также `2`.

### Полный манифест

Хешируется каноническое JSON-представление всех полей манифеста, кроме
`ManifestFingerprint`. В него входят идентичность, упорядоченные исходы, окно,
версия проекции, счётчики/границы raw, четыре отпечатка, версии алгоритмов и
нормализаторов, настройки и закреплённые ссылки. Время текущего чтения и ожидаемые
отпечатки не входят. Внешний набор не проверяется лишь по объявлению его hash.

## Проверки

```powershell
dotnet test .\PolymarketLab.DataCollection.Infrastructure.Tests\PolymarketLab.DataCollection.Infrastructure.Tests.csproj --filter FullyQualifiedName~ExperimentDataset
```

Интеграционные тесты требуют Docker и PostgreSQL 17 из Testcontainers. Проверены
точный выбор, изоляция версии/сессии, пропуски ledger, `[]`, связность проекции,
мутации входа и метаданных, конкурирующий commit между чтениями, режим READ ONLY,
неизменность всех таблиц схемы и независимые неизвестные финансовые сведения.

Первая реализация материализует набор в памяти и повторно читает события для
существующей терминальной проверки. Большие архивы требуют оценки памяти и времени
до расширения за пределы одной сессии. Поиск повреждённых перекрёстных ссылок также
читает заголовки, объявляющие выбранную session: схема не имеет отдельного индекса
по `normalized_events.session_id`. Миграция или новый индекс этим этапом не вводятся.
